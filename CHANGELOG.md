# Changelog

Add notes for the next release under **Unreleased** as you work. `build-and-bump.ps1` turns that heading into the version number and date when you release. Say when a release adds a migration - that decides whether rolling back to the previous tag is safe.

Versions before the first tagged release (up to 0.1.32) were deployed straight from `master` and have no notes here.

## Unreleased

## 0.6.19 — 2026-11-26

- **OMG build check (new setting `OMG_BUILD_CHECK`, default Refuse)** - a new build order of an OMG harness (made by hand, or by another plugin such as inventree-sales-order-builds) is checked against the last OMG sync: (1) the BOM hasn't been changed in InvenTree since (a line added, removed or a quantity changed - lines for the same part added together), (2) the sync's review items are all resolved, (3) the harness hasn't changed in OMG since (OMG's design fingerprint, one 5 s call to `/api/harness/<pn>/design-fingerprint/`). Refuse: the build isn't made - the reason starts "OMG: ..." (Sales Order Builds skips the line and tells the order's owner). Warn: it's made, with the problems in its metadata `omg_build_check`. Off. If OMG can't be reached, (1) and (2) still apply and (3) is noted on the build as a warning. Existing builds and parts that aren't OMG harnesses are never checked. Needs OMG with the 25 Nov (design fingerprint) update for (3) - without it a sync has no fingerprint and (3) is skipped.
- **Each sync records what it wrote** on the harness part (metadata `omg_sync`: the BOM as written, open review items, OMG's fingerprint and revision) and **sets InvenTree's BOM validation**: a clean sync validates the BOM, one that left review items marks it not validated. So InvenTree's own "BOM valid" means "matches OMG's last clean sync", and any later edit in InvenTree clears it.
- **Re-sync every harness once after updating** - until then a harness counts as "never synced from OMG" and Refuse stops its builds (or start on Warn).
- **Fix: a re-sync never changed the quantity of a BOM line that was already there** (nor did linking a review item to a part already on the BOM). InvenTree 1.7 works a line's quantity out of its *raw amount* on every save, so setting the quantity was quietly put back. Both now use InvenTree's `set_quantity`. Re-syncing corrects any harness whose quantities were left behind.
- **OMG Setup > Cavities: Max wire OD has its own heading.** It was an unlabelled box next to the delete button; it's now under an **Optional** divider below the range's main fields, labelled **Max wire OD (mm)** with a one-line hint. Panel changed: rebuild (no `-SkipBuild`).
- **Splice / loop / diode plugs: Side is now the part's own side** (the other half of the connector it plugs into) - a Mouser "receptacle" splice plug gets Side Receptacle, not Plug. Goes with OMG's matching change (a receptacle splice plug fits a plug connector). Existing plug-in parts imported with the old rule have the opposite Side - OMG flags them ("same side - it plugs in, so it's the other half"); flip their Side.
- **The push to OMG carries the part.** When a part, parameter or related part changes here, the plugin now sends OMG the part as it is now - name, IPN, description, active, every parameter, related parts, manufacturer and supplier part numbers and picture paths - and OMG saves it straight into its copy, instead of being told a pk and reading InvenTree back. Needs OMG with the 25 Nov (part data) update. OMG down: flagged and retried as before.
- **Fixed: wire gauge auto-fill used the built-in names and table.** It asked OMG for `/api/parts/wire-parameters/`, which OMG no longer has (a 404 in InvenTree's log each time a part parameter was saved). It now reads the gauge parameter names and your AWG / mm² table from OMG's part profiles, the same cached read the Part Setup panel uses.
- **Loop / splice plugs sync as assemblies.** The part OMG syncs a BOM into is made an assembly if it isn't one (a plug OMG created as a plain part) - InvenTree only takes BOM lines on an assembly. OMG now creates plug parts as assemblies itself (needs OMG with the 26 Nov plug update).
- **Fix: the Part Setup panel crashed** ("Cannot convert undefined or null to object") when OMG's part setup couldn't be read - e.g. while OMG restarts. It now shows the reason instead.
- All panels built against `@inventreedb/ui` 1.7.0 (was 1.5.0 - InvenTree 1.7 warned "Plugin version mismatch"). Panels changed: rebuild, or deploy the built `static/` files as they are (`-SkipBuild`).
- **Braid / covering colours.** A covering line OMG couldn't find a part for (a braid or trace colour with no Braid Yarn of that Colour and size) goes in the review queue with OMG's reason. The new OMG parameter **Colour** (role `covering.colour`) is offered from the colour list in Part Setup for yarn and covering parts.
- Tests (`omg_import_plugin/test_build_check.py`, 18; `omg_import_plugin/test_omg_refresh.py`, 5) run in InvenTree 1.7.3 with inventree-sales-order-builds 0.1.0. No migration.

A part number InvenTree doesn't have (or has twice) is flagged like any other.
- **Component Types Loop Plug, Ferrule and Cap** (OMG's current types): auto-fill and the Import from Supplier parameters type "loop plug" / "loop-back plug" / "shorting plug" parts as Loop Plug (Side the right way round, like a splice plug), "ferrule" / "bootlace" / "end sleeve" as Ferrule (with its Min / Max Gauge, like a contact), and dust caps / covers as **Cap** - OMG has no Cover type any more. "Splice plug" / "jumper plug" / "bussed" are now recognised in Mouser listings too. Run OMG's InvenTree Settings > Selection Lists > Component Type > Bring up to date first. No migration, no panel rebuild.
- Loop / splice plugs designed in OMG (its Plug Designer) need nothing new here: the plug is synced as its own harness assembly, and fitted on a harness it's one BOM line, as now.

## 0.2.0 — 2026-10-21

First tagged release - release as a minor version (`.\build-and-bump.ps1 -Bump minor`, 0.1.32 -> 0.2.0). No new migrations.

- **Releases and deploys:**
  - The server's `plugins.txt` now pins the plugin to a release tag (`...inventree_omg_plugin.git@vX.Y.Z`), so every update really reinstalls - no more `--force-reinstall`.
  - Only a tag deploys. CI (`.github/workflows/ci.yml`, replacing `deploy.yml`) checks the tag matches `version.py` and this changelog, publishes a GitHub release with these notes, and updates InvenTree. A push to `master` or a branch no longer touches the server.
  - `build-and-bump.ps1` builds the panels, moves the mouser_shared pin, checks the Python compiles, bumps the version, stamps this changelog, then commits and tags `vX.Y.Z`. New `-Bump`, `-Version`, `-SkipBuild` and `-Yes` options.
  - `tools/server-update.sh` (install as `inventree-omg-update`): backs up, pins `plugins.txt` to a tag, updates and restarts InvenTree, and confirms the installed version. `--check-only` and `--allow-downgrade` for checking and rolling back.
- **BOM quantities are exact on every sync:**
  - Each InvenTree part's quantity is added up across connectors, contacts, seals, blanks, wires, multicores, accessories, junctions and sub-harnesses, and written once. A part in two categories (e.g. a terminal sent as a connector and as a contact) used to keep only the last category's count.
  - An existing BOM line is corrected in place - nobody has to delete it first. Duplicate lines for one part, or InvenTree refusing the save, go in the review list instead of passing silently.
  - Terminals: one per different terminal symbol (`-` `+` `*` `#`), so a battery connector with `+` and `-` is 2.
- **Review queue:**
  - A flagged connector carries its real quantity, so resolving it adds the right count.
  - Resolving a review item **adds** its quantity to the part's existing line instead of replacing it.
  - Notes and warnings about a connector (quantity 0) never change the BOM when resolved.
- **Selection lists (restored):** the selection-list work from 13 October never reached GitHub - it's back. The OMG Part Setup panel offers OMG's lists as dropdowns (several values for an accessory's Connector Series), snaps typed values to the list's spelling, and InvenTree refuses a several-value parameter with a value not in its list. Parts created from Mouser (wizard or OMG pending parts) get OMG's parameters filled in.
- **Cavities - one source:** the Cavity Map is the one list of a connector's cavities, as ranges (`1-12`, `A-D`) or single cavities (`A, B, C, E`). The cavity grid's Series is picked from the Contact Series list (a series not in it is refused), and saving sets **Contact Count** to the number of cavities in the map.
